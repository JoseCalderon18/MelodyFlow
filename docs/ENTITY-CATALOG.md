# MelodyFlow — Proposed entity catalog

> **Status:** `MusicProject` and `GenerationJob` entities and EF mappings are implemented. `InitialMusicSchema` and `AddPostgresGenerationJobQueue` are generated but not applied; later-phase tables below remain proposals. This is the source of truth for domain schema fields. Review schema changes before applying migrations.
>
> **Sources:** MelodyFlow product requirements and architecture decisions. Properties explicitly labeled **YouTube-derived** correspond to the [YouTube Videos resource](https://developers.google.com/youtube/v3/docs/videos). That external API does **not** define our PostgreSQL schema. DTOs also do not generate tables: EF Core migrations use the configured entity model.

## Modeling conventions

- Main primary keys are application-generated `Guid` values (mapped to PostgreSQL `uuid`).
- Dates are UTC `DateTimeOffset` (`timestamptz` with Npgsql), optional dates are nullable.
- Store media files in the file system or object storage; PostgreSQL stores their `StorageKey` and metadata, **not** MP3/MP4/image binaries.
- `StorageKey` is a storage-relative key, not an arbitrary client-supplied absolute path. Resolve it through a storage service.
- Enums have explicit allowed states. Phase 1 maps enum values to PostgreSQL strings; changing a stored name later requires a migration.
- Prefer nullable values for genuinely unavailable metadata; `null` and zero do not mean the same thing.
- The default `GenerationJob.MaxAttempts` is **3 total attempts** (one original attempt + two retries). Count attempts consistently.
- Relations should represent real needs. **Do not add unnecessary foreign keys or cascades.** Never cascade-delete history, uploaded media or audit records by default.

## Baseline entities and columns

### MusicProject (`music_projects`) — phase 1

A production project, e.g. a one-hour lo-fi video, not an individual song.

| Property | Suggested C# type | Required / rule |
|---|---|---|
| Id | Guid | PK, generated by app |
| Title | string | Required, max 200 |
| Genre | string | Required, max 80; musical style, e.g. Lo-fi |
| Mood | string? | Optional, max 80; atmosphere, e.g. Relaxing |
| TargetDurationSeconds | int | > 0; no product maximum has been defined yet |
| Status | ProjectStatus | Draft, Active, Archived |
| CreatedAt | DateTimeOffset | Server UTC |
| UpdatedAt | DateTimeOffset | Server UTC |

`Genre` and `Mood` have distinct meanings. Keep their names; do not replace `Genre` with vague `Type` or `Kind`. The previously discussed `CoverSeedToken` is **not included** until a real reproducibility use case exists.

### GenerationJob (`generation_jobs`) — phases 1–3 queue foundation

Tracks an asynchronous request, its progress and retries; it is not itself a song or video.

| Property | Suggested C# type | Required / rule |
|---|---|---|
| Id | Guid | PK |
| MusicProjectId | Guid | FK → MusicProject |
| JobType | JobType | Music, Visual, Render, Publish |
| Status | JobStatus | Pending, Queued, Running, Retrying, Cancelling, Completed, Failed, Cancelled |
| RequestedParametersJson | string / structured JSON | PostgreSQL `jsonb`; validated snapshot, no secrets |
| ProviderName | string? | Optional name of external generator |
| IdempotencyKey | string? | Optional, max 200; unique within `(MusicProjectId, JobType)` when supplied |
| RequestFingerprint | string? | SHA-256 of normalized project/type/parameters; detects a key replay with changed payload |
| AttemptCount | int | ≥ 0; define whether incremented at start of an attempt |
| MaxAttempts | int | Default **3**; ≥ 1; 3 means one try + two retries |
| ProgressPercent | int | 0–100 |
| ErrorCode | string? | Safe, standardized code |
| ErrorMessage | string? | Sanitized; no credentials or sensitive provider payloads |
| CreatedAt | DateTimeOffset | UTC |
| StartedAt | DateTimeOffset? | UTC, optional |
| CompletedAt | DateTimeOffset? | UTC, optional |
| UpdatedAt | DateTimeOffset | UTC |
| NextAttemptAt | DateTimeOffset? | UTC; retry is eligible at or after this time |
| LeaseOwner | string? | Worker instance holding the current lease; max 120 |
| LeaseToken | Guid? | Random fencing token; never returned through the public API |
| LeaseExpiresAt | DateTimeOffset? | UTC lease deadline; expired work can be recovered |

Retry only transient failures; backoff starts at five seconds and is capped at five minutes. The queue uses PostgreSQL `FOR UPDATE SKIP LOCKED`, lease renewal and expired-lease recovery. A third failed attempt results in `Failed` unless a separate authorized manual retry policy applies. A worker cancellation request is cooperative; a queued/retrying job becomes `Cancelled` immediately.

### MusicTrack (`music_tracks`) — music library, phase 2

An individual audio track that **can be reused across multiple projects and rendered videos**.

| Property | Suggested C# type | Required / rule |
|---|---|---|
| Id | Guid | PK |
| **MusicProjectId** | **Guid?** | **Optional source/origin project** only; **not** the exclusive owner or a restriction on reuse |
| GenerationJobId | Guid? | Optional FK to producing job |
| Title | string | Required, max 200 |
| DurationMs | long? | Measured by media probe; > 0 if present |
| StorageKey | string | Required, storage reference; never audio bytes |
| Format | string? | e.g. mp3/wav; validate supported types |
| ProviderAssetId | string? | External provider reference |
| LicenseEvidenceKey | string? | Reference to proof of commercial rights |
| CreatedAt | DateTimeOffset | UTC |

**Change from the initial design:** Remove `SequenceNumber` from `MusicTrack`, because order belongs to the **use of a track in a video**, not to the reusable audio file itself. `MusicProjectId` is optional origin metadata; future project membership can use a separate join if needed.

### VisualAsset (`visual_assets`) — phase 2

A reusable image or short video clip (including clips downloaded manually from Google Flow). **It is not the final rendered YouTube video.**

| Property | Suggested C# type | Required / rule |
|---|---|---|
| Id | Guid | PK |
| MusicProjectId | Guid? | Optional source/origin project; avoid hard ownership if asset reused |
| GenerationJobId | Guid? | FK to creating job if generated through our workflow |
| AssetType | VisualAssetType | Image or Video |
| StorageKey | string | Required; file reference, no binary in DB |
| WidthPx | int? | > 0 if present |
| HeightPx | int? | > 0 if present |
| DurationMs | long? | For video assets; > 0 if present |
| Prompt | string? | Optional generation prompt; consider length and sensitivity |
| **IsManualUpload** | **bool** | **New: true** when uploaded/imported by the user; **false** when acquired automatically |
| **ProviderName** | **string?** | **New: nullable** (e.g. GoogleFlow, GoogleVeo); valid even for manual uploads |
| ProviderAssetId | string? | External provider reference if available |
| RightsEvidenceKey | string? | Storage reference to licensing/provenance evidence |
| CreatedAt | DateTimeOffset | UTC |

**Why both fields?** `IsManualUpload` answers *how it entered MelodyFlow*, while `ProviderName` answers *where it was created*. A manually imported Google Flow clip can therefore have `IsManualUpload = true` and `ProviderName = "GoogleFlow"`. The UI may provide an **optional select** for provider and an `Other` value; no provider selection is required. Backend controls the actual upload flag rather than trusting a client claim.

### RenderedVideo (`rendered_videos`) — phase 2

Final MP4 (or another rendered output) assembled from audio and visuals by FFmpeg.

| Property | Suggested C# type | Required / rule |
|---|---|---|
| Id | Guid | PK |
| MusicProjectId | Guid | FK → MusicProject |
| RenderJobId | Guid? | Optional FK → GenerationJob |
| StorageKey | string | Required; output video file reference, not binary |
| DurationMs | long | > 0; measured after render |
| WidthPx | int | > 0 |
| HeightPx | int | > 0 |
| Codec | string? | e.g. h264 |
| ContainerFormat | string | e.g. mp4 |
| FileSizeBytes | long? | ≥ 0 if present |
| ChecksumSha256 | string? | Optional integrity hash |
| Status | RenderStatus | Pending, Rendering, Completed, Failed |
| CreatedAt | DateTimeOffset | UTC |

The final video is **not** stored inside `VisualAsset`. A video may use **multiple reused `MusicTrack` records** and one or more visual assets; these relationships are defined by assembly records below.

### RenderedVideoTrack (`rendered_video_tracks`) — join for track reuse, phase 2

An explicit many-to-many association, with sequencing, between completed/planned rendered videos and reusable music tracks. Add this when implementing video assembly.

| Property | Suggested C# type | Required / rule |
|---|---|---|
| Id | Guid | PK; allows repeating the same track within a video |
| RenderedVideoId | Guid | Required FK → RenderedVideo |
| MusicTrackId | Guid | Required FK → MusicTrack; repeat uses allowed |
| SequenceNumber | int | ≥ 0, unique per rendered video |
| StartOffsetMs | long? | Optional position in final video |
| TrimStartMs | long? | Optional start position in source track |
| TrimEndMs | long? | Optional end position in source track |

**Design decision:** Use a surrogate `Id` rather than the composite key `(RenderedVideoId, MusicTrackId)`, because a song may appear several times in the same final video. Configure a unique index on `(RenderedVideoId, SequenceNumber)`.

Keep the trims/offset fields when composition supports them.

### RenderedVideoVisualAsset (`rendered_video_visual_assets`) — optional join, phase 2

Add **only when** a rendered video uses multiple clips or the same visual asset is reused across outputs.

| Property | Suggested C# type | Required / rule |
|---|---|---|
| Id | Guid | PK |
| RenderedVideoId | Guid | FK → RenderedVideo |
| VisualAssetId | Guid | FK → VisualAsset |
| SequenceNumber | int | Order within render |
| StartOffsetMs | long? | Optional placement |

For the very first one-background MVP, this join can be deferred and a simple selected asset reference passed in job parameters. Do not invent more relations before they are needed.

### YouTubeChannel (`youtube_channels`) — publishing phase

Channel linked to the application's authorized YouTube account(s).

| Property | Suggested C# type | Required / rule |
|---|---|---|
| Id | Guid | Internal PK |
| ExternalChannelId | string | Required, unique; YouTube `channelId` |
| Title | string | Required, channel display name |

## Relations (minimal, intentional)

- `MusicProject` 1:N `GenerationJob` and `RenderedVideo`.
- `MusicTrack.MusicProjectId` and `VisualAsset.MusicProjectId` may optionally indicate **origin**, not exclusive ownership; music and visuals may be reused across projects.
- `GenerationJob` may be referenced by its generated media record; no cascade deletion of historical jobs.
- `RenderedVideo` 1:N `RenderedVideoTrack` N:1 `MusicTrack`: **reusable songs**, including repeated appearances in one video.
- `RenderedVideo` 1:N `RenderedVideoVisualAsset` N:1 `VisualAsset` **only when multi-asset visual composition is implemented**.
- `RenderedVideo` 1:N `YouTubePublication`; `YouTubeChannel` 1:N `YouTubePublication`.
- `YouTubePublication` 1:N `YouTubeStatisticsSnapshot` once analytics exists.
- **Avoid adding relationship tables just for appearance.** No implicit cascade deletion of files or published content.

## Entity vs DTO vs external YouTube API resource

- **Entity**: modeled data stored in our DB, as EF Core maps it.
- **Request/response DTO**: API contract; not automatically persisted and not automatically a DB table.
- **Google `Video` model**: third-party schema; use Google's .NET client when integrating YouTube, without cloning the whole schema in our DB.

Example: `CreateMusicProjectRequest` may send Title, Genre and TargetDurationSeconds. The backend assigns Id, Status and timestamps. `YouTubeUploadRequest` supplies chosen upload settings; the backend builds Google's external request, uploads the video and updates `YouTubePublication` with the returned ID.

## EF Core implementation rules

1. Define entities in `Domain` where they are persistence-agnostic; put mapping in `Infrastructure` using `IEntityTypeConfiguration<T>`.
2. Configure required/optional fields, lengths, unique indexes, FK `DeleteBehavior`, value conversion and PostgreSQL array/`jsonb` choices explicitly.
3. Use a `DbContext` for mapped sets; **migrations create/alter tables**, not simply declaring the entity or DTO.
4. Review generated migration and SQL before `dotnet ef database update`.
5. Validate constraints such as `TargetDurationSeconds > 0`, `AttemptCount >= 0`, `MaxAttempts >= 1`, `ProgressPercent BETWEEN 0 AND 100`, positive media dimensions/durations.
6. Ensure unique `(RenderedVideoId, SequenceNumber)` for each rendered video's ordered tracks; repetitions of a `MusicTrackId` must be allowed.
7. Use indexes on `GenerationJob(Status, CreatedAt)` and appropriate other query patterns.
8. Ensure unique `ExternalChannelId` and filtered unique `(YouTubeChannelId, ExternalVideoId)` when video ID is known.
9. Never put credentials, MP3, MP4 or raw image bytes in PostgreSQL business tables.

**Change summary from earlier catalog:**

1. `VisualAsset` now has `IsManualUpload` and nullable `ProviderName`, including manually imported Google Flow clips.
2. `MusicTrack` can be reused across videos/projects; `SequenceNumber` moved to `RenderedVideoTrack`.
3. `RenderedVideoTrack` is an explicit join supporting the **same track more than once** in one video.
4. `MusicProjectId` on reusable assets is optional provenance, not exclusive ownership.
5. Full field tables now document `VisualAsset`, `RenderedVideo`, YouTube entities and optional tables.
6. `GenerationJob` defaults to **three total attempts**.
7. `CoverSeedToken` remains excluded and relationship complexity is deferred until needed.

## Open decisions for later phases

- `MusicProject.TargetDurationSeconds` is intentionally limited only to `> 0` until a product maximum is specified.
- Storage implementation and how storage keys map onto the local D: drive or a later object store.
- Arrangement planner choice (LM Studio or OpenRouter) and a commercially suitable SoundFont license.
- Whether multiple music-project references need a separate project/track library association later.
- Exact Google API write permissions, OAuth lifecycle and publication policy.

For entity-modeling agents: **read this catalog first**, compare with the actual code and migrations, present a migration diff, and request approval before destructive changes.
